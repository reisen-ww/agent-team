# 任务类型与可核验交付

组织协议可以复用，验收证据必须随任务改变。单纯问答/小编辑不因出现在下表就启用团队。混合任务可组合输出契约，避免拆成互相等待的过细工序。

| 类型 | 完整工作包的例子 | 有效交付证据 | 不能据此直接声称 |
|---|---|---|---|
| 编码/系统建设 | 有明确契约的功能、模块或纵向切片，包含实现和验证 | 固定产物、构建/测试/运行、接口与集成证据、未覆盖边界 | 单测通过即用户验收或生产可靠 |
| 研究/调研 | 能回答一个具体决策问题的证据调查 | 原始来源、读取/发布日期、事实/推断/未知、矛盾来源与可复现过程 | 摘要或搜索片段等于核读正文；人数等于事实正确 |
| 审查/审计 | 确定范围和风险类别的独立检查 | 原要求、被审版本、可复现问题、位置、影响、覆盖/未覆盖 | 没发现缺陷即没有缺陷；自查等于独立 |
| 数据处理/分析 | 有输入分区和输出契约的数据任务 | 数据版本、校验/统计、可复现实验、失败样本与汇总验证 | 更多执行者能增加单一数据库/算力资源的容量 |
| 内容/知识产物 | 定义读者、论点、证据和风格的完整章节/条目 | 来源、术语与跨章一致性、重复/冲突检查、编辑验收 | 字数等于质量；每章单独合格即整体一致 |
| 排障/运行任务 | 确定环境与影响面的诊断/获准修复 | 重现、假设检验、日志、修复或缓解、恢复和回归证据 | 临时缓解即根治；本地通过即可部署 |

研究中的探索路线可以并行，但共同前提和矛盾证据需要归并；编码中的高耦合事务/接口需要更强版本与集成约束。不能把适合探索的自由通信照搬成随意改写代码契约，也不能把每条研究线索都变成层层审批。

来源访问或实际运行能力缺失时，明确未验证部分，寻找已获授权的替代证据；禁止虚构数据、运行、审查者或引用。专业高风险问题沿用适用的人工/专业复核和授权边界。
