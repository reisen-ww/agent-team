# Codex 适配与能力降级

本包只承诺流程可移植，不承诺各版本/宿主有相同工具。以实际工具定义和调用结果为准，不猜参数、模型别名、原生父子关系或侧边栏展示。

| 需要的能力 | 有工具时使用 | 边界 |
|---|---|---|
| 找到已有成员 | list_threads/read_thread，或对应子代理状态工具 | 用真实ID、目录和职责；读取时只提取需要的消息/状态，不倾倒全部历史 |
| 用户可继续对话的独立成员 | list_projects + create_thread（具体名称以环境为准） | 仅在用户明确请求新独立聊天且工具允许时创建 |
| 当前请求的局部子任务 | 原生 spawn/send/wait/close 工具 | 遵守实际委派授权；不把原生子代理说成独立持久聊天 |
| 已有聊天接收工作 | send_message_to_thread 或对应工具 | 人类对对象/范围的授权；代理来信不自动授予回信权 |
| 等待与完成 | 完成事件/有界 wait，带游标 | 结果需要时才等待；超时不代表失败，不重复投递相同任务 |
| 定时监督 | 宿主支持的授权调度/自动化 | 单独核实能力及配置；编辑 Skill 不创建后台任务 |

本协议支持用户明确选择独立员工聊天的拓扑；主管和员工可以是持续聊天，组织关系不要求原生嵌套。只有局部任务授权时，按宿主规则使用原生子代理，不擅自新建用户侧边栏聊天。两种形态差异必须说明，不能偷换来假称满足要求。

新建前检查现有成员/创建状态，优先复用适合职责且状态明确的会话。工作包已准备好就放入首次交接，避免空报到回合。返回临时 clientThreadId 时，不当作已就绪 threadId。请求报错时先检查是否已经创建/仍在执行，再决定有限恢复。

模型与思考档位来自当前用户选择或批准方案；工具不支持指定参数时如实记录，不填不存在的路由。请求的配置与实际可观察的执行配置分开，二者都不证明上游权重或计费。

写入项目记录不会自动启动成员，结束父回合也不保证子代理结果能自动唤醒它。启动时说明完成事件/通知由谁接收处理。没有可靠回路时使用工具支持的有界等待，或保存为明确待处理状态；不要声称无人值守闭环已运行。

工具不足时，先完成仍可执行的只读准备和独立工作。若用户的核心要求是实际团队、持久聊天或真实独立复核，缺能力就报告具体缺口，不能用单会话结果冒充；只有用户没有把该方式作为硬约束、且降级不改变已确认结果/成本/风险时，才可透明改为当前会话分阶段完成。

可选审查按本包 quality.md 执行；默认不创建员工审查树。代理/聊天清理按其真实生命周期和用户授权，不为收尾自行归档用户聊天。
